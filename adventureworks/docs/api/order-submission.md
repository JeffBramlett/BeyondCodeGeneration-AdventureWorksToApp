# Order Submission API (Local Demo)

**State: ENABLED for the local contained demo only.** Project Owner decision, 2026-10-30. This contract supersedes the gates in [order-submission-design.md](order-submission-design.md) **for demo purposes only**. Production use, authentication hardening, antiforgery, and security review are explicitly out of scope.

## Endpoint

`POST /api/orders` — requires the existing `InternalStaff` fallback policy (Development Negotiate auth). Anonymous callers get `401`.

### Request (camelCase JSON)

```json
{
  "submissionToken": "3f2504e0-4f89-11d3-9a0c-0305e82c3301",
  "customerId": 29825,
  "billToAddressId": 985,
  "shipToAddressId": 985,
  "shipMethodId": 5,
  "lines": [
    { "productId": 707, "quantity": 3, "offerId": 2 },
    { "productId": 712, "quantity": 2, "offerId": null }
  ]
}
```

- `submissionToken`: non-empty GUID generated by the client once per order attempt.
- IDs must be positive. `lines`: 1–100 entries (`OrderDraftRequestValidator.MaximumLineCount`), `productId` unique, `quantity` 1–32767, `offerId` positive or `null`.

### Responses

| Status | When | Body |
|---|---|---|
| `201 Created` | Order recorded. `Location: /api/orders/{orderReference}` | Confirmation |
| `200 OK` | Same `submissionToken` already completed (replay) | Identical stored confirmation |
| `400` | Shape validation failed | `ValidationProblemDetails`, keys such as `submissionToken`, `customerId`, `lines`, `lines[0].quantity`, `lines[1].productId` |
| `409` | Same token currently being processed | `ProblemDetails` title `Submission already in progress` |
| `422` | Business revalidation failed | `ValidationProblemDetails` title `Order requires review`, keys such as `customerId`, `billToAddressId`, `shipToAddressId`, `shipMethodId`, `lines[i].productId`, `lines[i].offerId` |
| `503` | Reader or writer unconfigured/unavailable, or the write failed and was rolled back | `ProblemDetails` title `Order submission unavailable` (no SQL text or connection details) |

Confirmation body:

```json
{
  "orderReference": "SO75124", "status": "Recorded",
  "orderDate": "2026-10-30T08:43:55", "dueDate": "2026-11-06T08:43:55",
  "customerId": 29825, "billToAddressId": 985, "shipToAddressId": 985, "shipMethodId": 5,
  "lines": [
    { "productId": 707, "productName": "Sport-100 Helmet, Red", "quantity": 3, "offerId": 2,
      "offerDescription": "Volume Discount 2 to 14", "unitPrice": 34.99, "unitPriceDiscount": 0.02, "lineTotal": 102.8706 },
    { "productId": 712, "productName": "AWC Logo Cap", "quantity": 2, "offerId": 1,
      "offerDescription": null, "unitPrice": 8.99, "unitPriceDiscount": 0, "lineTotal": 17.98 }
  ],
  "subTotal": 120.8506, "taxAmt": 9.06, "freight": 25.00, "totalDue": 154.9106
}
```

Money values, `orderReference`, dates, and line totals are the **persisted values read back** from the database inside the write transaction. `offerId` is the SpecialOfferID actually stored (`1` "No Discount" when none was selected; `offerDescription` is then `null`). `orderDate`/`dueDate` are SQL `datetime` values in server local time without offset.

## Business revalidation (reader credential)

1. Customer exists; bill-to and ship-to address IDs are among the customer's order-options addresses; ship method is among order-options ship methods (`ICustomerReadStore.GetOrderOptionsAsync`).
2. Each product exists with a non-null `ListPrice` (`IProductCatalogReadStore.GetByIdAsync`).
3. `offerId` given: offer must be linked and currently eligible for the product and quantity using the same rule as `GET /api/products/{id}/eligible-offers` (`OfferEligibilityEvaluator`, UTC date window, MinQty/MaxQty). Its `DiscountPct` is read via `IOfferPricingReadStore` (product/offer-link-scoped query).
4. `offerId` null: product must be linked to SpecialOfferID 1 (`GetNoOfferPersistenceSupportAsync == true`), otherwise `lines[i].offerId` asks the user to select an eligible offer.

## Financials (server authoritative; `DemoOrderFinancials`)

- `UnitPrice = Product.ListPrice`; `UnitPriceDiscount = DiscountPct` (0 for no offer).
- `lineTotal = UnitPrice × (1 − UnitPriceDiscount) × Quantity` (matches SQL computed `LineTotal`).
- `subTotal = round(Σ lineTotal, 4)`; `taxAmt = round(subTotal × 0.075, 2, AwayFromZero)` (demo tax on discounted subtotal).
- `freight = 25.00` flat per order; `totalDue = subTotal + taxAmt + freight`.

Client-supplied prices are never accepted.

## Duplicate protection

`OrderSubmissionTokenRegistry` (singleton, API memory): tokens in flight → `409`; completed → `200` replay of the stored body (last 1000, 24 h). Any failure before commit (validation, `422`, `503`) releases the token so the user can retry with the same token. State is lost on API restart (accepted demo limitation). A replay returns the stored confirmation regardless of the replayed request body.

## Persistence

- Database: `AdventureWorks2022_Test` only, login `AdventureWorksTestWriter` (existing clone-only login). Credential: DPAPI CurrentUser, hex-encoded Unicode password at `%LOCALAPPDATA%\AdventureWorks\test-writer.credential`, overridable via `ADVENTUREWORKS_TEST_WRITER_CREDENTIAL_FILE`. Connection: `localhost`, `Encrypt=true`, `TrustServerCertificate=true`, `ApplicationName=AdventureWorks.DemoOrderWriter`. Missing/invalid credential → `UnconfiguredOrderWriteStore` → `503`.
- After open, `DB_NAME()` must be `AdventureWorks2022_Test` and `SUSER_SNAME()` `AdventureWorksTestWriter`, else fail closed (`503`).
- One `SqlTransaction`: `INSERT Sales.SalesOrderHeader (OrderDate, DueDate, CustomerID, BillToAddressID, ShipToAddressID, ShipMethodID, TaxAmt, Freight)` + `SCOPE_IDENTITY()`; one `INSERT Sales.SalesOrderDetail (SalesOrderID, OrderQty, ProductID, SpecialOfferID, UnitPrice, UnitPriceDiscount)` per line; read back header and detail values; commit. Typed parameters (`datetime`, `int`, `smallint`, `money`); no `OUTPUT` clauses (tables have triggers). Triggers update `SubTotal` and write `Production.TransactionHistory` — expected.
- `OrderDate` = server local time truncated to seconds; `DueDate = OrderDate + 7 days`.
- Any `SqlException` → rollback, sanitized `503`; details are logged server-side only.

The unused `PocWriterBoundaryConfiguration`/`PocWriterPrincipalGuard` (for the unprovisioned `AdventureWorksPocApiWriter`) are not used by this path.

## Tests

`OrderSubmissionEndpointTests` and `OrderSubmissionUnitTests` run offline with fake stores. `OrderSubmissionSqlIntegrationTests` inserts one real order into the clone and is skipped unless `ADVENTUREWORKS_RUN_SQL_WRITE_INTEGRATION_TESTS=1`, `ADVENTUREWORKS_WRITE_TEST_CUSTOMER_ID=<id>`, and both reader and writer credentials are configured.
