## Product outcome

Design the first usable workflow for authenticated internal staff to select a customer, assemble an order from the catalog, review it, and record it through the API. The intended outcome is an accurately recorded order, not a promise of inventory availability, shipment, fulfillment, or reservation.

## AW-034 approved offer eligibility defaults

The Project Owner approved the operational defaults below on 2026-10-27. The AdventureWorks schema verifies `Sales.SpecialOffer.StartDate`, `EndDate`, `MinQty`, nullable `MaxQty`, and the `Sales.SpecialOfferProduct` offer/product link; those fields do not establish the rules. The pure evaluator and authenticated eligible-offers and no-offer-persistence reads are implemented. Submission-time revalidation remains due. See `docs/data/adventureworks-p0-mapping.md` and `docs/product/p0-offer-eligibility-decision.md`.

| Rule | Approved operational interpretation | Remaining verification or limit |
|---|---|
| Offer/product link | A selectable offer must have a matching `Sales.SpecialOfferProduct` row for the requested product. A link alone is not eligibility. | The composite order-detail FK is verified enabled/trusted. Offer 1 marker support is verified for 295 linked products only; 209 lack a link. Revalidate at submission. |
| Date interval | Evaluate the API's current UTC instant against a half-open interval: `StartDate <= instant < EndDate`. Start is inclusive; end is exclusive. | Implement and test. |
| Time source and timezone | Use the API's current UTC instant at eligibility evaluation and submission. Interpret timezone-less SQL `datetime` offer values as UTC; do not apply a client clock or local-time conversion. | The Project Owner explicitly selected this application mapping despite unknown historical provenance. Do not claim the source system stored values as UTC. |
| Quantity interval | For the requested positive line quantity, require `quantity >= MinQty` and, when `MaxQty` is non-null, `quantity <= MaxQty`. Both quantity bounds are inclusive; null `MaxQty` means no upper bound. Evaluate each line independently. | Pure evaluator boundary tests pass; revalidate against current data at submission. |
| No offer | Display “No offer applied.” For persistence only, Offer 1 may represent no promotion, even outside its promotion dates, but it is never an implicit/selectable offer and never affects price/discount. | Verified only where the product's Offer 1 link and enabled/trusted pair FK are present; in the clone this is 295 products. The other 209 products remain blocked. Revalidate marker capability at submission; no schema change or arbitrary fallback. |
| Submission recheck and stale choice | Re-evaluate the selected offer against the product link, current UTC instant, and submitted line quantity immediately before accepting the order. If eligibility or applicable pricing changed since review, do not submit with stale terms or silently substitute another offer. Return current choices and require renewed user review and explicit confirmation before retrying. Preserve the draft product and quantity where possible, but mark the offer as requiring review. | Implement and test. |
| Price display | These defaults define eligibility only. Do not derive a price, discount amount, or final price from `DiscountPct`; do not present a final price until a separately approved price authority and calculation policy exist. | Price authority/calculation remains subject to the existing approval and financial-write gates. |

No database write or production order route is authorized by these recommendations.

## AW-016 address-option DTO clarification

For implementing the already-approved fail-closed address-eligibility rule, the proposed option fields are a reasonable minimum: `AddressID`, address lines 1 and 2, city, postal code, and linked address-type labels needed to distinguish eligible choices. Ship-method choices need only `ShipMethodID` and `Name`. Do not include phone numbers, person names, state/country metadata, or freight rates. This is an implementation clarification, not new eligibility or business policy: return address options only after verifying eligibility for the selected customer, fail closed when it cannot be verified, and revalidate at submission.
